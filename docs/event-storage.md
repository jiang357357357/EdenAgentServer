# 流式事件存储与上下文读取

`0026_event_storage.sql` 为 `session_events` 增加内部字段 `payload_base_seq`。
字段为空时，`payload_json` 仍是完整事件；非空时，它是相对于同会话前序事件的带类型 JSON 补丁。
已有事件无需重写。包含新编码事件的数据库应使用支持该迁移的 Server 读取，不应交给旧版二进制回放。

根会话的 `agent.message_update` 使用 `StreamEventWriter`：每条消息单独持有写入状态，只有事务提交成功后才更新状态。首条更新保留完整快照；其后只有在补丁更小且依赖链未达到 63 层时保存补丁，否则写入新的完整快照。文本追加保存后缀，结构变化和流重置也可以完整还原。消息结束事件始终完整保存。

`list_events` 和 `list_event_page` 在同一个 SQLite 查询快照内获取所需的前序依赖，再恢复原始载荷。分页游标、事件 ID、序号和对外 RPC 结构不变；广播仍发生在持久化提交之后，并携带完整事件。

这降低了累计文本快照的存储量，没有减少每条事件的事务次数，也没有改变完整消息在模型适配器、广播和完整历史回放中的内存与传输成本。新写入流的单条记录最多需要应用 63 个补丁。此前以几何间隔写入的旧记录仍可读取，但旧依赖链不会自动重写，因此该上限只保证新记录。固定间隔快照牺牲部分压缩率，不承诺总存储量随最终消息长度线性增长。

模型上下文通过 `list_context_events` 读取：排除流式更新等无关事件，保留最新压缩记录及其尾部消息、导演最近可读消息、助手缓存与技能状态、子智能体通知和角色动作。压缩之前的普通聊天历史仍按原有语义参与上下文；通知和角色动作目前仍保留完整记录。

验证命令：

```bash
cargo test -p eden-agent-store compact_streams_replay_exactly -- --nocapture
cargo test -p eden-agent-app filtered_history_preserves_context
cargo test -p eden-agent-store --test event_recovery_load -- --ignored --nocapture
```

语音 Blob 对象 URL 由前端播放组件持有的 `ObjectUrlScope` 管理。同一作用域内去重下载，清空会话音频或卸载时撤销 URL 并取消下载；试听在结束、失败、替换或卸载时释放。不同播放组件互不撤销对方使用中的 URL。

主会话和子智能体在事件持久化失败时会关闭事件通道、取消本轮执行并返回原始存储错误，不再等待已经无人消费的队列，也不忽略子智能体的事件写入错误。

Mon 同步通过 `list_sync_snapshot_events` 最多读取 200 条近期稳定事件及最新压缩/角色状态，排除根会话和子智能体的消息更新、工具进度事件。历史完成消息按页读取，旧消息 ID 恢复仅查询本轮消息边界。`0027_sync_projection_index.sql` 为稳定事件读取提供索引。

WebSocket 每条连接最多并发 16 个普通 RPC，取消、权限回复和问题回复另有 4 个名额；超过容量的请求立即返回 `-32004`。客户端应按请求 ID 匹配响应，需要顺序的操作应等待前一个响应。连接断开不会撤销已接受的操作；发送超时则关闭连接，客户端通过持久化状态重新同步。会话删除通知携带 Store 在删除事务中获取的 `runtimeOrigin`，转发时不再依赖已删除的会话记录。
